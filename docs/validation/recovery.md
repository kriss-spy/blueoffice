# Reconnect and recovery

Verified 2026-10-08 against installed Hermes `f1247d2e0146bbd8edd4e510b9e67e0d259509a4`. [Native evidence](recovery/native-report.json), [browser evidence](recovery/browser-report.json), [restored selected context](recovery/desktop.png), [independent reviews](recovery-review.md).

The office persists normalized ordered changes, agent/session associations and command receipts in one SQLite transaction. A read transaction captures the agent snapshot and its journal high-water mark. SSE sends later changes with the stable journal ID and revision. Browser application skips duplicates, requires contiguous revisions, and rejects a different journal. The retained journal defaults to 512 events; missing legacy bodies or a retention gap causes a complete checkpoint instead. Retention never removes the saved agent's pending-request registry or command fingerprint ledger.

Native event order and deduplication happen before streaming redaction. Missing native events are fetched with the per-session cursor through `session.events.since`; bare replay envelopes use the same reducer as live events. The independent open-request registry restores exact frame and inner IDs, owner/session/epoch, supported input schemas and confirmed batch locks. A browser reconnect reauthenticates and reconciles live owned children before receiving its checkpoint. Offline or failed streams disable controls; aborted older connection attempts cannot replace current state. Commands are never submitted by reconnect code.

Native Hermes has no atomic snapshot-plus-watermark API. A truncated replay therefore takes a public `session.activate` snapshot between two matching native sequence readings, with bounded retries. A changing or unavailable checkpoint leaves state Unknown. History content does not prove a terminal outcome: only a matching `message.complete` supplies terminal-turn evidence. Unexplained missing requests become lost; explicit cancellation distinguishes resolution and expiry. A delivered response can be recorded as closed when the authoritative registry confirms absence, without claiming its tool action succeeded.

The native in-flight assistant buffer spans the whole turn. Recovery separates known sealed interim segments from its unfinished tail, preserves earlier messages, and keeps an explicit active-message association for later deltas and terminal replacement. Before publishing a checkpoint, the unfinished tail seeds the streaming credential redactor; a held credential prefix remains held through the next delta. Hidden reasoning, private metadata, native tool arguments/results and error bodies do not enter the recovery projection.

A supervisor restart retains identities, conversation associations, messages, receipts and known requests. Unacknowledged admission and decision delivery remain Unknown; no prompt, reply or question lock is resent. An explicit replacement obtains a new epoch and retires old pending requests as lost. It does not invent a continuation of the former tool. Stored-history resume is a separate explicit workflow in #12.

Verification:

- Independent process fixtures cover missing/reordered/duplicate native events, omitted request frames, retained and truncated journals, unknown prompt admission, exact once-only command delivery, confirmed locks, stale targets and replacement. Checkpoint regressions preserve a sealed interim plus a final response, continue a partially streamed message without duplication, and test a credential split across the snapshot boundary against every published snapshot and journal change.
- SQLite/reducer and HTTP tests cover consistent durable replay, cleared fields and collection order, duplicate application, invalid/gapped revisions, stable journal identity and full snapshot fallback. Public-history tests exclude private metadata and preserve known tool outcomes.
- Installed Hermes with a synthetic provider inside the disposable bubblewrap namespace retains a batch lock and an answerable exact approval after reconciliation. The final measured native approval reconciliation was 13 ms; an earlier run measured 510 ms. Both exclude provider response time and meet the provisional 3-second target. Actual Deny and Allow-once sentinel outcomes still pass. No host credentials or live model calls were used.
- Visible Chromium with two configured agents preserves the selected second agent and transcript scroll position through refresh. It observes disabled controls while offline, waits for a new authenticated session, and restores the exact approval in 63 ms with the fixture backend. A real server SIGKILL/restart automatically reauthenticates, retains history/identity/selection, reports the old request Unknown, and sends zero duplicate prompts or replies. Explicit runtime replacement marks that request lost. No page errors.

Commands: `npm test`, `npm run test:protocol`, `npm run build`, `python3 scripts/hermes_probe.py --suite office --output artifacts/recovery`. Browser evidence was recorded with the Playwright skill's visible Chromium runner and an isolated fixture data directory.

Final checks: 49 TypeScript tests, 19 Python tests and the production build pass. Both independent reviews have zero remaining findings.
