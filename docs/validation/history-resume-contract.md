# Proposed owned resume contract for issue #12

This is a protocol proposal for review, not implemented or admitted resume capability. Installed Hermes revision: `f1247d2e0146bbd8edd4e510b9e67e0d259509a4`. Native references below are relative to that source root. Existing wire evidence is `docs/validation/hermes-contract.md` and `scripts/probe_contract.py:204`: cold owned resume returns a new live ID, `resumed`/`session_key` preserve stored identity, the new process has a fresh replay epoch, and a foreign profile's stored ID is rejected. The candidate implementation reserves a conversation transition under the office's mutation/ownership guard, verifies current lifecycle/freshness/idle state and exact profile marker, retires old request admission, stops only the exact owned runtime, and launches a fresh owned process with a fresh office epoch. New uses `session.create`; Resume uses only the verified exact stored target and reconciles native requested/resolved ID fields. Name, avatar and desk stay on the same office agent. Any startup/resume failure leaves a visible failed/stopped runtime state and coherent historical binding/selection; it never silently creates another conversation or replays a command.

The proposed auto-continue policy belongs in managed profile configuration and its runtime route/policy verification. Existing profiles need a verified stopped-profile update under the existing kernel lease and settings readback. This is not a read-only history change, so it must be a separate #12 implementation reviewed before execution. A synthetic fresh crash-marker probe must show zero provider requests after Resume until a new explicit prompt, and an old request/epoch must remain rejected.

The proposed route preflight reads only the exact stored/resolved row's allowlisted route identity on the server. It exposes supported/unsupported reasons, not raw `model_config`, credentials or private paths. A synthetic conflicting stored endpoint/model/API family test must prove refusal before background agent construction; a valid owned stored route must prove the intended mock endpoint/API family after a new explicit prompt. Native healing, stored endpoint overrides and lazy agent construction cannot be accepted from assumptions.

Observed external history remains inspectable with Resume disabled and a visible reason until a synthetic native import/copy/resume flow into an owned profile is proved. Passing a foreign profile name to `session.resume` is not an acceptable shortcut: native `_Resume.profile_home` can address that foreign profile and does not acquire the office's ownership lease for it. The current contract advertises no external takeover or external resume support.
