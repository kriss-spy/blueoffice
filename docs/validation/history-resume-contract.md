The candidate implementation reserves a conversation transition under the office's mutation/ownership guard, verifies current lifecycle/freshness/idle state and exact profile marker, retires old request admission, stops only the exact owned runtime, and launches a fresh owned process with a fresh office epoch. New uses `session.create`; Resume uses only the verified exact stored target and reconciles native requested/resolved ID fields. Name, avatar and desk stay on the same office agent. Any startup/resume failure leaves a visible failed/stopped runtime state and coherent historical binding/selection; it never silently creates another conversation or replays a command.

The proposed auto-continue policy belongs in managed profile configuration and its runtime route/policy verification. Existing profiles need a verified stopped-profile update under the existing kernel lease and settings readback. This is not a read-only history change, so it must be a separate #12 implementation reviewed before execution. The original zero-provider-request assumption was corrected by native observation below: passive inference, prompt replay and actions must remain absent, while tightly allowlisted model metadata requests are separately recorded. An old request/epoch must remain rejected.

The proposed route preflight reads only the exact stored/resolved row's allowlisted route identity on the server. It exposes supported/unsupported reasons, not raw `model_config`, credentials or private paths. A synthetic conflicting stored endpoint/model/API family test must prove refusal before background agent construction; a valid owned stored route must prove the intended mock endpoint/API family after a new explicit prompt. Native healing, stored endpoint overrides and lazy agent construction cannot be accepted from assumptions.

Observed external history remains inspectable with Resume disabled and a visible reason until a synthetic native import/copy/resume flow into an owned profile is proved. Passing a foreign profile name to `session.resume` is not an acceptable shortcut: native `_Resume.profile_home` can address that foreign profile and does not acquire the office's ownership lease for it. The current contract advertises no external takeover or external resume support.

## Implemented policy and corrected native evidence

The owned transition is implemented by `Office.conversation` and an exact trusted history lookup. It reserves the assistant against prompt/settings/start/stop races, validates the expected foreground binding (including an unstarted null binding), preflights before retiring an idle child, and rechecks after asynchronous preflight. Exact command retries return the existing receipt before checking the obsolete target. Busy, attention and uncertain live state are refused. New and Resume create a fresh owned process and office epoch; failed Resume restores coherent previous identifiers with a visible failed lifecycle and never falls back to New. The requested stored ID, resolved compression-tip ID, source/profile provenance and fresh live ID are retained separately. Existing managed profiles obtain `desktop.auto_continue.enabled=false` through an explicit stopped Settings save with native readback; route and policy are checked again under the owned process lease. External history remains unsupported for Resume.

Owned Resume uses native `defer_history=true`, `eager_build=false`, `omit_messages=true`; it does not use the lazy/watch branch. **Deferred hydration still builds an agent**: `tui_gateway/server.py:2746–2747` calls the auto-continue policy check and `_start_agent_build` after loading history. The earlier one-second zero-request observation (`artifacts/history-resume-probe/1791473626076076559`) ended before that background build and is not admission evidence. Repeated attempts (`1791473847885863126`, alongside the earlier cold-path failures) showed metadata POSTs and remain available for diagnosis.

The product invariant is no implicit inference, old prompt replay or tool/action execution. Native model metadata lookup during explicit Resume is permitted only at the verified managed host: exact metadata GET paths and POST `/api/show` containing only `{"name": managed_model}`. This corrects our stronger initial assumption that Resume must make zero HTTP requests. Native `agent/model_metadata.py:1429–1434` supplies that model-name-only POST; its JSON response is used only for model capability/context metadata. No transcript or tool data belongs in a metadata request. We did not patch Hermes, bypass stored route policy, or invent context limits to suppress these lookups.

The replacement synthetic proof is `artifacts/history-resume-probe/1791511134333800888/report.json`. For **both** GLM Chat Completions and Muse Responses it waits for `session.info` from `_announce_built_agent` (`tui_gateway/server.py:1052–1064`) after construction, then observes a 1.5-second quiet interval. Its synthetic-only request recorder retains method/path/body without credential headers, rejects unexpected requests, and separates allowlisted metadata from inference. Each model produced 12 metadata requests and zero passive inference calls, with no message-start/completion or tool/action events. One explicit new prompt then made one inference call through the correct API family/model; the crash-marker prompt was absent from inference payloads. Exact compression resolution, foreign profile, conflicting model/endpoint and profile-follow model mismatch, and unchanged database bytes during read-only preflight are also asserted. Real provider calls were zero because the probe runs in a private network namespace with only the synthetic loopback service.
